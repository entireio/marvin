Stage 02

Electronics

Six signal wires, one motor driver, one microcontroller. There is no schematic and no board yet — this is breadboard wiring, honestly labelled.

Table 02.3 — Wiring

ComponentPartConnection
MicrocontrollerESP32-C3 SuperMini—
Motor driverDRV8833 breakoutIN1→5 · IN2→6 · IN3→20 · IN4→10
Drive motors2 × brushed DC gearmotorDRV8833 outputs A and B
Head pan servoSG90-classGPIO 4

A and B are not yet formally assigned to left and right. Full pin map.

Costs you an evening — 01

Motor B is wired inverted, on purpose

IN3 and IN4 are swapped so that a positive speed on both channels drives forward, without the firmware correcting per side. Wire it the obvious way and one track runs backwards.

Costs you an evening — 02

A weak battery browns the board out

If Marvin connects over Bluetooth and then drops the moment the motors draw current, the supply is sagging. It is almost never the firmware.

The firmware also drives all four motor pins LOW at the very start of startup, before anything else, because ESP32 pins float during boot and a floating H-bridge input makes the tracks lurch.

Assemble

This is the largest gap in the project, and it sits in the middle of its most important page. Rather than pretend otherwise, here is the format the steps will take, and exactly what each one needs.

Step format — worked example

01

Press the four wheels onto the motor shafts

One drawing, one sentence, and the part numbers involved. No paragraphs. A builder should be able to work from the drawing alone and use the sentence only to check.

Parts

Time

What this section needs

A step sequence

Somewhere between twelve and twenty steps, in build order: drivetrain, chassis closure, neck, head, then electronics. Written by whoever assembles the next one, while assembling it.

One drawing per step

Wordless, single fixed axonometric angle, arrows for motion, part numbers for identity. Exported from the same CAD master as Fig. 02.

A hardware list

Screw sizes and counts, bearings, motor dimensions. Without it, no step can honestly say “fix with two M3 × 8”.

Stage 04

Flash

Requires PlatformIO. Connect the board over USB and run the flash script from the repository root.

$ cd firmware && ./flash.sh

Then open a serial monitor at 115200 baud. You get a prompt:

Marvin> R120

Type a command and the head moves. Bluetooth advertising starts automatically under the name Marvin; you do not need to enable anything.

First checks

  1. Tracks still. If they lurch at power-up, the motor pins floated — reflash.
  2. R90 then T57. The head should centre smoothly, not snap.
  3. M80, then S. Both tracks forward, then stop.
  4. D. Demo mode. Put it on the floor first.

Stage 05

First drive

Serve the controller app, open it in Chrome or Edge, and pick Marvin from the device picker. One thing trips up nearly everyone:

It must be served, not opened

Web Bluetooth only works in a secure context. Open the file with file:// and the Bluetooth API is simply undefined — the Scan button does nothing at all.

$ cd controller && ./serve.sh # then http://localhost:3000
