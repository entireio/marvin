Drive

Seven commands, each a letter and a number, over a browser or any Bluetooth terminal. Leave it alone and it explores by itself.

Setup

Connect

The controller is a web page with no build step and no framework, so it can be served from anywhere. It talks to Marvin over Web Bluetooth, which has two hard requirements.

Requirement — a secure context

It must be served, not opened. Web Bluetooth exists only over https:// or localhost. Double-click the file and the API is undefined — the Scan button does nothing, silently.

$ cd controller && ./serve.sh → http://localhost:3000 · Scan · choose “Marvin”

Requirement — browser support

BrowserWeb Bluetooth
Chrome — desktop, AndroidYes

Bluetooth Low Energy allows one client at a time. If Marvin is missing from the picker, something else is already holding the connection — or it is not powered.

Controls

The command language

One line-based text protocol, identical over USB serial and Bluetooth. Case-insensitive, one command per line. The shaded band on each scale is the range the firmware will accept.

R <angle>

Head rotation — pan

Full sweep, centred at 90.
e.g. R90

T <angle>

Head tilt

Clamped to protect the neck.
e.g. T45

M <speed>

Both motors

Negative reverses.
e.g. M128

A <speed>

Motor A — one track

Pivot by driving one side.
e.g. A200

B <speed>

Motor B — the other

Inputs wired inverted; positive is still forward.
e.g. B200

S no argument

Stop

Both tracks to zero. The head holds its angle.

D no argument

Toggle demo mode

Put it on the floor before you send this.

Values are clamped, not rejected

Ask for T200 and you get 85° — the mechanical limit — not an error. The protocol assumes you meant “as far as it goes”.

Any movement cancels the demo

You never have to switch modes first. Send a command and Marvin stops exploring and does as it is told.

Any BLE terminal will do

Bluetooth uses the Nordic UART Service, so a generic terminal app drives the robot as well as the project's own. The UUIDs are in Reference.

Autonomous behaviour

What it does when left alone

Send D and Marvin runs a hand-choreographed sequence: arcs, pivots, straight runs, and pauses where the head sweeps as though scanning. The head usually moves before the body turns, which is what makes it read as intent rather than mechanism.

Nothing about it is generated or random. It is a table of movements someone wrote by hand, with asymmetric durations chosen to avoid a metronomic feel. The annotated sequence is on the home page.

If something goes wrong

Troubleshooting

Five symptoms account for almost every report so far.

SymptomCause
Scan button does nothingNot a secure context — use localhost, not file://
“Web Bluetooth is not supported”Firefox or Safari — use Chrome or Edge
Marvin not in the device pickerNot powered, or already connected elsewhere — BLE allows one client at a time
Connects, then drops immediatelyLow battery — the microcontroller browns out when the motors draw current
Robot lurches on power-upMotor pins floating during boot
