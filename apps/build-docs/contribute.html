Embedded C++

Firmware

The firmware uses PlatformIO and the Arduino framework, configured for an ESP32-C3 SuperMini. Connect the board over USB and run ./flash.sh from the firmware directory to build and upload it.

The firmware has one class per peripheral and a shared configuration header. Timer-based updates keep movement running alongside Bluetooth and serial input. The head servos move gradually toward each target angle for smoother motion.

Adding a command touches four places: the parser, the on-device help text, the controller app's cheat sheet, and the protocol documentation. Keep these in sync so the documented commands match the firmware.

Web

Software

The controller app and this website use plain HTML, CSS, and JavaScript. Both are served as static files, with no framework or build step.

Use relative asset paths and internal links so the site also works when hosted under a subpath. The controller needs HTTPS or localhost for Web Bluetooth.

CAD and printing

Mechanics

Make geometry changes in the CAD model and export updated meshes. Edits made only to an STL will be lost when the mesh is exported again.

Parts are numbered 01–09 across the drawings, tables, and mesh files. Give new parts the next available number and keep existing numbers unchanged.

Aim to keep individual mesh files under 50 MB. Check the tessellation settings when exporting large meshes, and preserve enough detail for printing.

Assembly documentation

HELP NEEDED

Photograph your build

The assembly instructions need photos or drawings for each step. If you build a Marvin, photograph the process and note any unclear instructions. We also need a face-plate mesh, tested print settings, and measurements of the assembled robot.

PCB design

Electronics

The proposed electronics use two boards connected by a six-wire harness. The specification lists components, I²C addresses, and pin assignments; schematics and PCB layouts are still needed. The specification is in Electronics.

The working prototype uses hand-soldered modules. Its supply can sag when the servos and motors run together, resetting the microcontroller and interrupting Bluetooth. The proposed board separates the logic and motor supplies; this still needs to be built and tested.

Project conventions

Follow these conventions when making changes.

  1. 01One configuration header. Every pin and tuning constant lives in config.h. Use those definitions in drivers so pin assignments can be updated in one place.
  2. 02The main loop never blocks. Every periodic behaviour is a timer-based state machine. No delay() — it would stall Bluetooth and the console.
  3. 03One class per peripheral, in its own header and source pair.
  4. 04A new command touches four places. Parser, on-device help text, the app's cheat sheet, and the protocol documentation.
  5. 05No build step in the controller app. Keep it as static HTML, CSS, and JavaScript.
  6. 06CAD is the master; meshes are derived. Never edit a mesh directly.
