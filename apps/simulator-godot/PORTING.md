# Marvin Simulator: Godot port

A faithful port of the macOS game in `apps/simulator-macos` to Godot 4.7 (.NET/C#), so it runs on Windows as well as macOS. The goal is that it looks and plays as close to the macOS game as possible.

**The macOS game is the reference, not a dependency.** Never modify anything under `apps/simulator-macos`. Read it, run it, capture it, and compare against it.

The C# assemblies are compiled with optimisation in every configuration (`<Optimize>true</Optimize>` in both projects): the Godot editor binary runs a project's Debug build, and unoptimised C# made the world build and every frame several times slower (see "Performance").

`tools/env.sh` sets `DOTNET_ROOT` (`~/.dotnet`) and `GODOT` (`~/Applications/Godot_mono.app`). In this shell, `cat` and `ls` are aliased to missing tools: use `command cat`, `command ls`, or the Read and Write tools. Use `gtimeout` (GNU coreutils) to bound any Godot run.

## Translation rules

**Mirror the Swift code.** Port file by file and keep every type, member and function name **verbatim**, including Swift's camelCase member names. Do not restructure, "improve" or simplify behaviour. If something cannot be mirrored, note the deviation in a `// PORT:` comment.

**Numbers.**
- Swift `Double` → `double`, `Float` → `float`, `CGFloat` → `double`.
- Swift `Int` is 64-bit. Use `long` wherever values can exceed 32 bits: hashes, seeds, RNG state, products of indices. Plain `int` is fine for small counts and indices.
- Wrapping operators `&+ &- &*` → C#'s default unchecked arithmetic on the same width. Bit shifts on unsigned types → the same unsigned C# types.
- `x.rounded()` is round-half-away-from-zero: `Math.Round(x, MidpointRounding.AwayFromZero)`. C#'s default `Math.Round` is banker's rounding and is **wrong** here. `.rounded(.down)` → `Math.Floor`, `.rounded(.up)` → `Math.Ceiling`, `.rounded(.towardZero)` → `Math.Truncate`.
- `Int(x)` truncates toward zero: `(long)x`. `truncatingRemainder(dividingBy:)` → `%` on doubles. `%` on integers is truncated in both languages.
- `Float` maths uses the float functions (`MathF.Sin`), `Double` maths uses `Math.Sin`. On macOS .NET calls the same Darwin libm as Swift, so results should be bit-identical. Keep operation order exactly as written; do not use FMA.

**simd.** Core provides `Double2`, `Double3`, `Double4`, `Float2`, `Float3`, `Float4`, `QuatD`, `QuatF`, `Double3x3` and `Float4x4`, plus a static `Simd` class mirroring Apple's functions (`Simd.dot`, `Simd.length`, `Simd.length_squared`, `Simd.distance`, `Simd.normalize`, `Simd.cross`, `Simd.min`, `Simd.max`, `Simd.mix`, `Simd.clamp`, quaternion `act` and `slerp`). They follow Apple's header formulas:
- `dot` sums the lane products left to right;
- `length = sqrt(dot(x, x))`;
- `normalize(x) = x * (1 / sqrt(dot(x, x)))`;
- `distance = length(x - y)`.

**Value semantics.** Swift structs **and Swift arrays/dictionaries** are values; copying one and mutating the copy never affects the original. C# arrays and `List<T>` are references. Where Swift copies a struct that holds arrays (for example `var stopped = state; stopped.stop()`) and then mutates either side, the C# port must deep-copy, or the mutation leaks. Port value-type models as C# `struct`s with explicit `Clone()`/copy where they hold collections, and audit every copy site.

**Randomness.** Seeded generators (custom `RandomNumberGenerator` structs, LCGs, hashes) must give identical sequences. Swift's `Double.random(in:using:)`, `Float.random(in:using:)`, `Int.random(in:using:)`, `Bool.random(using:)` and `shuffle(using:)` / `shuffled(using:)` / `randomElement(using:)` have specific stdlib algorithms. Port them **exactly**, from the Swift stdlib source, into `Marvin.Core.SwiftRandom`. Unseeded calls (`SystemRandomNumberGenerator`, plain `.random(in:)`) may use `System.Random.Shared`.

**Core helpers (src/Core).** Beyond `Simd` and `SwiftRandom`, `Swift.cs` ports Swift/Darwin behaviour the app also needs: `Swift.format` (exact `String(format:)`, Darwin rounding), `Swift.description` (Swift number/array printing), Darwin's `hypot` (libm on macOS; elsewhere `Swift.portableHypot`, its algorithm reproduced bit for bit, see "Release builds and Windows"), stable `sorted`, `stride`. Measured: Apple's `simd_cross`, quaternion maths and `stride` use fused multiply-add; .NET's `double.Hypot` differs from Darwin's in 10 % of calls. Never format numbers with `$"{x}"`/`ToString()` for user-visible or report text; use `Swift.format`/`Swift.description` (the current culture would print decimal commas or U+2212 minus signs). Value-type models that hold collections (`DirtRacePhysics`, `PostRaceEscape`, `RacePerformance`, `SandDeformation`) have `Clone()`; call it wherever Swift copies one and mutates either side. Structs with Swift default values have explicit parameterless constructors: never use `default(T)` or `new T[n]` for them.

**Reference numbers.** `reference/simulation-checks-swift.txt` comes from a **debug** Swift build (`swift run SimulationChecks`); an optimized Swift build differs in the last digits. The C# port matches the debug build byte for byte on macOS. The shipped game is the release build, so a long chaotic simulation can drift from it after a one-ulp difference (TrailRaceSmoke's three-lap race, see "Race smokes against macOS").

**Collections.** Swift `Dictionary`/`Set` iteration order is unspecified. Where Swift code depends on iteration order, the result was already nondeterministic: keep the C# behaviour deterministic and note it.

## SceneKit → Godot

Coordinate systems match: right-handed, +Y up, cameras look down −Z, metres.

| SceneKit | Godot |
|---|---|
| `SCNNode` without geometry | `Node3D` |
| `SCNNode` with geometry | `MeshInstance3D` (or a `Node3D` with a `MeshInstance3D` child when the node also has children with their own transforms) |
| `position`, `scale` | `Position`, `Scale` |
| `eulerAngles` (pitch, yaw, roll) | Set `RotationOrder = EulerOrder.Zyx` and `Rotation = euler`, or build `Basis.FromEuler(euler, EulerOrder.Zyx)`. **Measured:** SceneKit's matrix equals Godot's ZYX basis. Godot's default YXZ order is wrong. |
| `simdOrientation` / quaternion | `Quaternion` (x, y, z, w) |
| `pivot` (re-measured) | **Rendering** applies the pivot inside the node: world = parent · T · R · S · pivot⁻¹ (a SceneKit render shows the pivot point at the node position). SceneKit's **model API** (`worldTransform`, `convertPosition`, `worldPosition`) instead reports parent · pivot⁻¹ · T · R · S, i.e. `position + R·S·q − pivotTranslation`. The facade reproduces both (`SCNNode.RenderLocal`/`ModelLocal`). |
| `isHidden` | `Visible = false` |
| `opacity` | `GeometryInstance3D.Transparency = 1 - opacity` |
| `castsShadow` | `CastShadow` |
| Shadow-only proxy via `categoryBitMask` | `CastShadow = ShadowCastingSetting.ShadowsOnly` |
| `renderingOrder` | `Material.RenderPriority` (sorting among transparents); opaque order is by depth |
| `SCNLevelOfDetail(worldSpaceDistance:)` | One `MeshInstance3D` per level with `VisibilityRangeBegin`/`End` |
| `SCNGeometrySource`/`Element` | `ArrayMesh.AddSurfaceFromArrays`. Godot has `UV`, `UV2` and `CUSTOM0`-`CUSTOM3` (up to 4 floats each, `ArrayFormat.FormatCustomRgbaFloat`) for extra channels, plus `Color`. |
| Triangle winding | **SceneKit front faces are counter-clockwise, Godot's are clockwise.** Reverse each triangle's index order when converting (or the faces are culled). |
| `SCNBox`/`SCNSphere`/`SCNCylinder`/`SCNPlane`/`SCNFloor` | `BoxMesh`/`SphereMesh`/`CylinderMesh`/`PlaneMesh`, or generate the same tessellation in code. Match segment counts and chamfers. |
| `SCNMaterial` `.physicallyBased` | `StandardMaterial3D` (metallic/roughness) or a `ShaderMaterial` |
| `.lambert` / `.constant` | Diffuse-only shading / `ShadingMode.Unshaded` |
| `diffuse` colour (sRGB `NSColor`) | Albedo `Color` (Godot colours are sRGB; it linearises them) |
| Shader modifier `.geometry` | `vertex()` in a `.gdshader` |
| `.surface` | `fragment()` (set ALBEDO, ROUGHNESS, METALLIC, NORMAL_MAP, EMISSION, ...) |
| `.fragment` (post-lighting colour) | No direct hook. The facade composer emulates SceneKit's ordering; translate with the idioms in "Shader modifier translation guide" below. |
| `SCNLight` `.directional` | `DirectionalLight3D`. Measured: SceneKit intensity 1000 = Godot `LightEnergy` 1.0 exactly (same Lambert + GGX response). |
| `.ambient` | `Environment.AmbientLight*` |
| Shadow map size | One directional atlas shared by all directional lights (`SceneKitCalibration.DirectionalShadowAtlas`, 8192); blur, bias and splits are refitted per camera (see "Lights, cameras, scenes, views") |
| `SCNCamera.fieldOfView` (vertical) | `Camera3D.Fov` (vertical with `KeepAspect = Height`); same `Near`/`Far` |
| `wantsHDR`, exposure, bloom | Measured: SceneKit HDR with fixed exposure is a plain linear clamp, so tonemap = Linear; bloom = Glow (calibrated levels). |
| `screenSpaceAmbientOcclusion*` | `SCNSsaoEffect`: SceneKit's own SSAO kernels as a compositor effect (Godot's SSAO stays off) |
| Scene fog (linear start/end) | `Environment` fog in depth mode (`FogMode = Depth`, begin/end, curve 1.0 for linear) |
| `lightingEnvironment` (IBL image) | `Environment` sky (`PanoramaSkyMaterial` or a sky shader), ambient and reflections from the sky |
| `background` colour | `Environment.BackgroundMode = Color` |
| `SCNView.antialiasingMode` | `Viewport.Msaa3D` |
| AppKit views, Quartz drawing | `Control` nodes; immediate-mode drawing in `_Draw()` |
| SF Pro / SF Mono | `SystemFont` with `FontNames` `["SF Pro Text", "SF Pro", ".AppleSystemUIFont"]` / `["SF Mono", "Menlo"]`; on Windows it falls back to Segoe UI / Consolas (and the signs' Avenir Next Condensed to Bahnschrift) |
| `NSEvent.keyCode` | `InputEventKey.PhysicalKeycode` |
| Command key (menu key equivalents, `modifierFlags.contains(.command)`) | Command on macOS, **Control** elsewhere (`NSEvent.commandIsControlKey`); help texts show `KeyEquivalent.command` ("⌘" or "Ctrl+") |
| `NSWindow`, `NSToolbar`, `NSApp.mainMenu` | The Godot window (`extend_to_title` on macOS), a title bar/toolbar drawn by the facade, the macOS global menu (Godot `MenuBar`/`NativeMenu`) or an in-window menu bar elsewhere. Which conventions apply is `Platform.macUI` (`MARVIN_PLATFORM_UI=windows` runs the Windows ones on a Mac) |
| `Timer` 1/60 s tick | `_Process(delta)`, with the same dt clamping and pause rules; frames capped at the content view's `preferredFramesPerSecond` (`Engine.MaxFps`) |
| UserDefaults / Application Support | `user://` (`ConfigFile` for settings at `user://UserDefaults.cfg`, the Swift JSON format for scores at `user://motocross-v4-scores.json`) |
| GCD background world build | `Task.Run` for data generation; node-tree changes on the main thread |
| AVAudioEngine | Godot audio buses and `AudioStreamPlayer`s (or an `AudioStreamGenerator` mixer), keeping gains, rates, pans and filters |

**Assets.** Load from `res://assets/...`. Marvin's `geometry.bin` and the JSON meshes are raw files read with `FileAccess`. Textures are imported with mipmaps (sync writes `.import` files).

## SceneKit facade

`scripts/SceneKit/` (namespace `Marvin.SceneKit`, global usings in `GlobalUsings.cs`) re-creates the SceneKit, AppKit-image and Metal API that `Sources/MarvinSimulator` uses, on top of Godot. Port app files **against the facade**, keeping SceneKit names: `SCNNode` is a `Node3D`, `SCNMaterial` compiles to a Godot `ShaderMaterial`, `SCNView` is a `Control`. All "make it look like SceneKit" work lives in the facade, calibrated against SceneKit renders (see "Calibration"). Do not reach around it with Godot nodes in app code unless a `// PORT:` comment explains why.

```csharp
let node = SCNNode(geometry: g); node.position = SCNVector3(1,2,3); node.eulerAngles.y = a; node.castsShadow = false; parent.addChildNode(node)
var node = new SCNNode(g);       node.position = new SCNVector3(1,2,3); node.eulerAngles.y = a; node.castsShadow = false; parent.addChildNode(node);
```

### Measured SceneKit semantics reproduced by the facade

Measured with Swift probes on macOS 27 (reproduce with `tools/scenekit-reference/FacadeReference.swift`):

- **eulerAngles**: R = Rz(z)·Ry(y)·Rx(x) (pitch applied first; Godot `EulerOrder.Zyx`). Values read back as written in single precision (`eulerAngles.y = 4` reads 4, not a normalised angle; 0.7 reads 0.699999988079071); `rotation` reads back as written; whichever of euler/orientation/rotation was written last is authoritative.
- **Single precision**: a node's `position`, `scale`, `eulerAngles`, `orientation`, `rotation`, `pivot`, `transform` and `opacity` are stored as `Float` (position 0.1 reads 0.10000000149011612, opacity 0.48 reads 0.47999998927116394), and `worldPosition`/`convertPosition` answer in `Float` (Swift probe, macOS 27). The facade rounds the same way (`SCNNode.Quantize`: the `ref` properties cannot round a write, so every read rounds first), which makes the smoke test's `marvinToR2D2HeightRatio` (`neutralHeight x root.scale.y / sceneHeight`) the macOS 0.5555555673827447. Matrix products are still evaluated in double and rounded, so chained world transforms can differ from SceneKit's float arithmetic in the last float bit. `SCNLight.intensity` and `SCNCamera.zNear` stay double.
- **pivot**: see the table above (render vs model API).
- **Defaults**: `SCNMaterial()` is `.blinn`, diffuse white, specular black, mipFilter `.nearest`, wrap `.clamp`; a new `SCNGeometry` has one default material. `SCNLight()` is omni 1000, `castsShadow` false, shadowRadius 3, shadowBias 1, orthographicScale 1, maximumShadowDistance 100. `SCNCamera()` fov 60 (vertical), zNear 1, zFar 100, `wantsExposureAdaptation` true, bloomThreshold 0.5, bloomBlurRadius 4. `SCNNode` castsShadow true, categoryBitMask 1.
- **Colours**: SceneKit shades in linear extended sRGB. `srgbRed`/`deviceRed`/`white:`/gray-family named colours use the sRGB curve; `calibratedRed` is Generic RGB (gamma 1.8 then a primaries matrix); `calibratedWhite` is gamma 1.8. Light, ambient and fog colours are converted the same way. Diffuse/emission/multiply textures are sRGB-decoded; roughness/metalness/ambientOcclusion/normal textures are raw.
- **Vertex colours** are raw floats that multiply `_surface.diffuse` *before* `.surface` modifiers (a modifier that writes the diffuse replaces them). Alpha premultiplies diffuse: `NSColor` alpha twice for `.constant`/`.lambert`/`.blinn`/`.phong` but **once for `.physicallyBased`**; vertex and texture alpha once for every model. A transparent PBR surface keeps its full specular highlight (glass-like), and `.physicallyBased` materials **ignore `transparency`** in the default `.aOne` mode (measured: opaque result). A geometry's elements are drawn in order with depth writes, so a double-sided transparent box shows only the face drawn first.
- **selfIllumination**: a physically based material whose `selfIllumination` is set, or whose shader modifier merely mentions `_surface.selfIllumination` (even `_surface.selfIllumination.rgb *= 1.0`), takes its diffuse image-based light from selfIllumination (albedo x selfIllumination, black by default) instead of the lightingEnvironment's irradiance; ambient lights and the specular reflection are unchanged (Swift probe on spheres). SceneKit's SSAO does not darken that self-illumination term (its `selfIlluminationOcclusion` is 0 by default: a self-illuminated plane in a corner keeps 0.96-1.0 of its light where a plain one keeps 0.46), so the composer adds it after the SSAO factor. Not reproduced: the term uses SceneKit's diffuse response (`add_irradiance_from_selfIllum`, Hammon factors: 1.11-1.33 x albedo at normal incidence for albedo 0.21, measured), the composer uses albedo x selfIllumination (the game's selfIllumination is black). DirtCoating's modifier mentions it, so the robots get no diffuse sky light in SceneKit: under the race light R2-D2's body is lit by the ambient light, the suns and its reflections only.
- **Order of transparent geometry**: SceneKit draws transparent geometry back to front by the view-space depth of its world bounding-box centre, ties in scene-graph order (Swift probe: a box whose centre is 13 m deep but 29.5 m to the side is drawn after one 15 m deep on the view axis; the node's origin does not matter). Godot sorts by the Euclidean distance to the AABB centre, so `SceneKitRuntime.SortTransparent` sets each transparent instance's `SortingOffset` to distance - depth whenever a view syncs its camera. Before, the town's street ribbon was drawn over the trampled-sand overlay, which SceneKit draws last over the streets: the street-level sand in `--dust-visibility-test`'s town view and in navigation's street-out/return views was 14% too dark, with a dark smear behind Marvin (6.4 -> 1.3/255 and 9.4 -> 3.1/255).
- **No normal source**: shaded with flat face normals facing the viewer (measured: a horizontal quad without normals lights exactly like one with +Y normals for either winding, a shared-vertex ridge shades per face). The composer derives them per pixel (`VariantFlags.NoNormals`).
- **Lighting**: directional 1000 lm = irradiance 1 (Lambert, no 1/π) plus GGX specular (F0 0.04, exact height-correlated Smith visibility, no multi-scatter energy compensation). Godot uses an approximate visibility term and energy compensation, so the composer gives PBR materials a matching `light()`. Ambient lights add albedo x intensity/1000 for every lit model, independent of metalness and without specular; `.constant` ignores them. `lightingEnvironment` diffuse and specular follow SceneKit's own roughness responses (fitted); reflections are sharp on smooth materials (the game's sky probe shows a hard horizon line in a chrome sphere) and the reflected intensity scales with f0 (no multi-scatter energy compensation, as for direct light). `.emission` adds after lighting; `.multiply` multiplies the lit colour (`mix(1, m, intensity)`).
- **HDR**: `wantsHDR` with fixed exposure is a linear clamp (emission k renders k, clipped at 1), confirmed on the game-like scenes (suns, emissive patches). Bloom only above `bloomThreshold`; its blur scales with the render size (the same glow levels fit at 400 and 820 pixels high).
- **SSAO** is ported from SceneKit itself (`scripts/SceneKit/SCNSsao.cs`): its kernels `scn_ssao_downsample`, `scn_ssao_compute`, `scn_ssao_blur_x/_y` and `scn_ssao_upsampling` in `SceneKit.framework/Resources/default.metallib`, disassembled from their AIR bitcode (llvmlite reads it), and the uniforms SceneKit binds (logged with a Metal API probe that swizzles the encoders). It is Scalable Ambient Obscurance: a full-resolution view-space normal/depth texture with box-filtered mips; `screenSpaceAmbientOcclusionDownSample` 2 and `SampleCount` 9 (SceneKit's defaults, hidden properties the game never sets): a checkerboard of the nearest / farthest sample of each 2x2 block, 9 taps on a 7-turn spiral rotated per pixel by a hash, a disk radius of 1000 x `radius` / depth full-resolution pixels (independent of the field of view and the drawable size; SceneKit binds `radius` 1000 x R, `radius2` its square and `intensity` I / radius^6, so the falloff term cancels), per tap max((v.n - `bias`) / (v.v + 1e-4), 0), A = max(0, 1 - 2 x I x sum / 9); two 13-tap bilateral Gaussian blurs (stride 2, taps beyond `DepthThreshold` 0.2 in depth or `NormalThreshold` 0.3 in a normal component dropped) and an edge-aware upsampling. A numpy model of these kernels reproduces SceneKit's measured profiles in front of a wall within 0.01-0.03; the port's occlusion maps (Calibration.cs `CAL_EXP=ssao`, a Swift twin renders the same scene) are within 0.006 mean of SceneKit's from 2 to 12 m. SceneKit's SSAO darkens ambient light and image-based light, reflections of every roughness included (the same ratio from roughness 0.02 to 0.8 for metals and dielectrics; its shader source multiplies the global probe's specular by the surface's ambient occlusion), **of physically based materials only**: constant, lambert and blinn materials receive none but still occlude (a lambert box darkens the ground like a PBR box).
- **SSAO depth/normal pass**: SceneKit renders its own pass (a Metal capture of its normal/depth texture, `texspy`, shows what it holds): opaque geometry writes its interpolated vertex normal and view z, ignoring normal maps and `.surface` normals (a normal-mapped ground gets exactly the same SSAO as a flat one) and without turning the normals of a double-sided material's back faces towards the viewer (a double-sided plane seen from behind is darkened to 0.70-0.73 by a wall 0.4 m behind it, from the front not at all); pixels nothing is drawn to are cleared to z = -infinity; transparent geometry is left out. Materials with a `.geometry` shader modifier are drawn with their own shader, which writes their **shaded colour and alpha** into the texture (an orange PBR box: (0.37, 0.07, 0.03, 1)): z = +1, behind the camera. A tap that lands there finds a point behind the camera, which occludes surfaces facing the camera but hardly the ground (an identity modifier on a box keeps 0.994 of its ambient light at the base, 0.853 without, and the ground beside it keeps 0.97-0.99 instead of 0.94-0.96). BinarySky's dome, drawn first without the depth test, puts its sky colours with alpha 1 behind everything: every sky pixel is at z +1, so in race and town views the robots and walls against the sky are darkened (the robot close-ups under the race light: mean occlusion 0.83 / 0.75 / 0.90 on R2-D2's wheels / Marvin's gear / R2-D2's front; the port had 0.88 / 0.81 / 0.94 with the sky as far plane, and has 0.83 / 0.75 / 0.90). The port builds the texture from Godot's depth prepass and normal-roughness buffer: a material that bends its normal (normal map, `.surface` normal) or is double-sided lights with its shading normal through a varying (`scn_lit_n`) and leaves the vertex normal, negated on back faces, in `NORMAL` for the prepass; the composer tags every material in `ROUGHNESS` at the end of `fragment()` (0: occluder; 0.6: `.geometry` modifier, stored at z +1; 1: transparent or depth only, stored as the far plane), which nothing reads afterwards (`light()` uses its own roughness varying; Godot's environment BRDF cancels for f0 = f90 = 1); pixels the prepass left empty are at z +1 when the view's scene shows a `.geometry`-modified sky drawn without the depth test (`SceneKitRuntime.HasSsaoSky`), else far. Nearly everything in the town has a `.geometry` modifier (city tint, crowd gait, ground tints), so SceneKit's town shows almost no SSAO. Not reproduced: `.geometry`-modified physically based materials receive the occlusion SceneKit computes from their colour as a normal at z +1 (a modified ground over nothing gets 0.64 at intensity 0.70, a modified box 0.98-0.99); the port gives them none.
- **isNode(_:insideFrustumOf:)** tests the node's world-space axis-aligned bounding box (the box around the transformed local bounding box), not the oriented box: a unit box rotated 0.6 rad leaves the frustum at x = 4.64-4.68 (world AABB 4.653, oriented 4.261). Visibility traces of the town people now match SceneKit frame for frame.
- **Fixed shadow box** (`automaticallyAdjustsShadowProjection = false`): shadows exist only inside the light's box: |x|, |y| <= `orthographicScale` around the light node (light space) and depth `zNear`..`zFar` along the light; receivers outside are unshadowed and the box edge is sharp; inside, shadows do not depend on the camera distance. Casters in front of `zNear` do not cast. Measured with a 13 x 13 post grid under a tilted light (orthographicScale 5): `tools/godot -- --shadow-box-probe DIR` renders the same scenes through the facade (0.0-0.4/255, the only difference being the clipped caster). The composer clips the shadow to the box (`scn_shadow_box0/1`) and `FitShadows` covers the box in view (see "Lights, cameras, scenes, views"). Town captures: market-vendor 6.2 -> 1.35/255, outer town 3.8-8.0 -> 1.2-2.0, town overview 8.5 -> 5.7 (the rest there is missing race content).
- **Fog**: linear in Euclidean view distance, `pow(f, fogDensityExponent)`, mixed in linear space; enabled when `fogEndDistance > fogStartDistance`.
- **Shadows**: forward shadows remove `shadowColor.alpha` of that light. Deferred shadows leave the light itself unshadowed and multiply the **final** colour (all lights, ambient, sky light, emission) by `1 - alpha x shadow`; faces turned away from the light count as shadowed (thin double-sided planes seen from behind darken too), and a large `shadowRadius` self-shadows lit curved/sloped surfaces as a function of the angle to the light only (measured on spheres of 0.15 m and 1 m, map 2048/4096, orthographicScale 2/10: identical): radius 3 none; 8: plateau 0.28 from 37 deg; 16-32: 0.44 from 27 deg. `shadowBias` has no measurable effect (0.001, 1 and 10 identical, forward and deferred). Shadow maps hold the faces turned towards the light (a single-sided plane shadows what lies under it only when it faces the light). Casters are pushed away from the light by a slope-scaled bias (measured with fixed boxes, `GroundBiasProbe`): a casting ground leaves the sunlit walls standing on it lit down to 2 mm at elevations 5-35 degrees, and a 1 cm plate's shadow on the ground is half there once its gap is about 1.3 cm + 2.2 shadow texels (2.4 / 4.8 / 7.5 / 15 cm for texels of 0.49 / 1.42 / 2.83 / 5.66 cm); lit walls do not self-shadow below 75 degrees to the light. Penumbra (10-90%) of a fixed shadow box is about 1.2 x `shadowRadius` texels of the light's own map in light space (map 4096 over 116 m, radius 3: 11.5 cm on a floor lit at 60 deg). Transparent geometry casts opaque shadows. In the sandbox's deferred setup SceneKit also darkens lit surfaces by 4-6% at grazing view angles (none from above); not reproduced. Measured (`CAL_EXP=deferredview`, Swift twin `sb.swift`/`sbmap.swift`): it depends on the antialiasing mode, as if the deferred pass rebuilt the position from the depth of MSAA sample 0 (4x: 0.375 px up from the pixel centre, which puts it below a floor receding upwards) along the ray through the pixel centre: with shadow alpha 1 the far floor is 70% shadowed with 4x MSAA, 7% without antialiasing and none with 2x (sample 0 below the centre); the shadowed share grows with that point's drop below the surface (0.2-0.3 at under 1 mm, 0.4-0.8 at 3-5 mm) but differs between views at equal drops, and without antialiasing it is still 2-13%. Moving Godot's shadow lookup to the same point (`LIGHT_VERTEX`) changes nothing: Godot's shadow biases absorb millimetre offsets.
- **SCNShape**: curves are flattened with the path's `flatness` (default 0.6, so small curves become chords), overlapping contours are unioned whatever their winding, contained contours become holes, tiny contours vanish (the robot-eye ovals do not render in SceneKit). `extrusionDepth` 0 is a single +Z face.
- **SCNText**: pen starts at x = 0, baseline at y = 1.0 (monospaced system font, sizes 1 and 2). The geometry is the font's glyph outlines tessellated like `SCNShape` (the text's `flatness`, overlapping contours filled): Godot's `TextMesh` cannot triangulate the overlapping contours of the variable system fonts (SF Mono, SF Pro) and left the sandbox's beacon numbers empty. SceneKit draws SF Mono Semibold's "1" without the foot bar the outline has (facade test "12"); not reproduced.
- **Primitive sources**: SceneKit's primitive geometries expose unit template sources (24 vertices for any box). The facade builds real tessellations instead: chamfered boxes with `chamferSegmentCount` (default 10), `(n+1)²`-vertex spheres, 3-element cylinders (side, top, bottom), measured UV layouts.

### Geometry and mesh conversion

Each `SCNGeometry` becomes one `ArrayMesh` (built lazily, rebuilt when sources or the material grouping change), one surface per run of consecutive elements that draw with the same material, triangles in element order, vertices compacted (SceneKit draws elements in order; Godot's order among one instance's transparent surfaces is undefined, and fewer surfaces mean fewer draw calls). Materials repeat cyclically (`materials[element % count]`, measured). Triangles are re-wound (SceneKit front faces are counter-clockwise, Godot's clockwise). Attributes:

| SceneKit source | Godot attribute | Shader access |
|---|---|---|
| vertex, normal | `VERTEX`, `NORMAL` (missing normals: +Z placeholder in the mesh, flat face normals in `fragment()`) | `VERTEX`, `NORMAL` |
| tangent (or generated from texcoord 0, per-vertex averaged, OpenGL Y+ normal maps) | `TANGENT` (+ sign for `BINORMAL`) | `TANGENT`, `BINORMAL` |
| color | `CUSTOM3` (RGBA float; Godot's `COLOR` attribute is 8-bit and the game stores times and signed slopes there) | `COLOR` (the composer copies `CUSTOM3` into `COLOR` first) |
| texcoord channel 0, 1 | `UV`, `UV2` | `SCN_TEXCOORD0`/`1` |
| texcoord channels 2-7 | `CUSTOM0.xy/.zw`, `CUSTOM1.xy/.zw`, `CUSTOM2.xy/.zw` (RGBA float) | `SCN_TEXCOORD2` ... `SCN_TEXCOORD7` (vertex stage) |

`levelsOfDetail` become one `MeshInstance3D` per level with `VisibilityRangeBegin/End` (screen-space LODs are converted for a 1080-pixel, 48° view). SceneKit measures a `worldSpaceDistance` from the node's origin, Godot a visibility range from the instance's AABB centre (both measured: a level whose geometry sits 8 m off its node origin switches by origin distance in SceneKit), so world-space LOD instances get a custom AABB centred on the node origin that encloses every level. A set `boundingBox` becomes `ArrayMesh.CustomAabb`. `node.opacity` multiplies down the hierarchy into `GeometryInstance3D.Transparency`.

Godot-only: `SCNGeometry.godotAutomaticLevelsOfDetail` (set by `DirtCoating.install` on every robot part) gives the Godot mesh Godot's own screen-space mesh LODs (`ImporterMesh.GenerateLods`, generated when the mesh is prepared), each used while its error stays below `SceneKitCalibration.MeshLodThreshold` (0.5) pixel of the camera's view. SceneKit draws the robots' CAD meshes at full detail everywhere (Marvin: 695,000 triangles in 23 parts); in Godot's shadow maps they were the most expensive geometry of a frame. By default (`MeshLodForCamera`) the camera draws the levels too, so the robots' silhouettes can move by up to half a pixel. With Shadow quality Exact on the Settings screen, `MARVIN_SCN_CAL=Exact` (or `MeshLodForCamera=0`) the node's instance draws the full mesh for the camera (`LodBias` 1e20) and a shadow-only twin instance with the same mesh and materials casts its shadows from the levels, which leaves camera images unchanged (see `docs/performance.md`, GPU optimisation pass and "Hard shadows and camera mesh LODs").

Godot-only, so that Godot can draw equal geometry as one instanced draw (its forward renderer joins consecutive draws of the same mesh surface with the same material; `docs/performance.md`, "Draw calls"): primitive geometries (`SCNBox`, `SCNSphere`, `SCNCylinder`, `SCNPlane`) with the same shape parameters and material layout share one Godot mesh (`SCNGeometry.MeshShapeKey`; `DirtCoating.install` copies every robot part, so Marvin's 112 track shoes were 112 meshes), and a geometry's own matrix shader arguments are per-instance values (see "Shader composer"). The same arrays are drawn, so images are unchanged.

### Shader composer

`ShaderComposer` turns each material (plus the geometry's own `shaderModifiers`/`setValue` arguments, which make a per-geometry variant) into Godot shader code; identical code shares one `Shader`. Variants are keyed by render priority (`renderingOrder`, clamped to -128..127), geometry-owned shading, vertex colours and the lighting features of the node's scene (below). Geometry-owned shading is compared by value (`ShaderComposer.ShadingKey`: the geometry's modifier text, numbers by value, textures and material properties by reference), so equal geometries share one Godot material; a geometry's own matrix arguments (declared `mat4` by its own modifiers) are Godot `instance uniform`s set on each mesh instance (`SCNGeometry.InstanceArguments`; four `vec4` columns and a `#define`, as Godot has no matrix instance uniforms). DirtCoating's per-part `dirtToBody` is such an argument: every part of a robot that uses one SCNMaterial (and has the same `dirtRolling`) now shares one Godot material instead of having its own. Numbers stay material uniforms: passed per instance, a divisor changed a few dirty-robot pixels by one 8-bit step. The generated `fragment()` follows SceneKit's order:

1. `_surface` preparation: diffuse (colour x texture x intensity x vertex colour, premultiplied), roughness/metalness (texture component), emission, ambient occlusion, multiply, normal map applied to `NORMAL` (so modifiers see the mapped normal, as in SceneKit).
2. `.surface` modifiers (geometry's first, then the material's).
3. Lighting composition (direct light for every lit model runs in the generated `light()`, see "Measured SceneKit semantics"): `.constant` writes the colour to `EMISSION` (and `ALBEDO` for deferred shadows) with Godot ambient and reflections zeroed; legacy models set `IRRADIANCE` = SH(lightingEnvironment) + ambient lights. For `.physicallyBased`, at the end of `fragment()` (after `.fragment` modifiers) **all ambient light is routed through `IRRADIANCE`**, multiplied by SceneKit's SSAO (`scn_ssao`, unless a `.geometry` modifier keeps the material out of SceneKit's SSAO pass) and by the material's AO in Godot: albedo x (SH diffuse x SceneKit's roughness response x (1 - metalness) + ambient lights) + sky specular (pre-filtered radiance x SceneKit's specular response x an analytic split-sum BRDF, no energy compensation); a material whose modifier uses `_surface.selfIllumination` adds albedo x selfIllumination after the SSAO factor. `RADIANCE` is zero. Godot then sees `ALBEDO = 1`, `METALLIC = 0`, `SPECULAR = 2.5` (f0 = f90 = 1, so Godot's environment BRDF x energy compensation is exactly 1 and `RADIANCE` passes through); the material's albedo and metalness reach `light()` through varyings.
4. Transparency: `ALPHA = diffuse alpha x transparency` when SceneKit would blend (`#pragma transparent`, alpha < 1, translucent texture, non-alpha blend mode).
5. Fog: `FOG = vec4(fogColor, SceneKit linear fog)` (Godot's own fog is never used).
6. `.fragment` modifiers.

Render state: `blendMode` -> `blend_mix/add/sub/mul`; `writesToDepthBuffer` -> `depth_draw_opaque/always/never` (transparent SceneKit materials still write depth; depth-writing transparent materials also get `depth_prepass_alpha`, which puts them in Godot's shadow pass, opaque above alpha 0.1, because SceneKit casts their shadows); `specular_occlusion_disabled` (Godot 4.4+ dims sky reflections by ambient luminance, SceneKit does not); `readsFromDepthBuffer = false` -> `depth_test_disabled`, or, with a negative `renderingOrder` (sky dome), the geometry is pushed to the far plane so everything else covers it; `colorBufferWriteMask = []` -> depth-only (`blend_mul` with white); `isDoubleSided`/`cullMode`. `.lambert`/`.blinn`/`.phong` = Lambert diffuse, no specular unless `specular` is set (approximated with GGX).

`.geometry` modifiers live in `vertex()`, which Godot also runs for shadow maps and the depth prepass, so deformed casters (CitizenMotion, dune patches) cast deformed shadows as in SceneKit. After them, in Godot's shadow pass only (`IN_SHADOW_PASS`), `vertex()` applies SceneKit's caster slope bias for the lights with a fixed shadow box: the shadow camera's axis identifies the light (the box's z row), and the vertex moves away from it by `scn_shadow_slope` (`ShadowSlopeBiasTexels` x the light's SceneKit texel) x the tangent of the angle between the vertex normal and the light, at most `ShadowSlopeMax`. Geometry without normals (the town's shadow proxies) gets none.

The generated `light()` (all lit models): Lambert diffuse; for PBR, or legacy models with a `specular` colour, GGX with Godot's D and Fresnel, the exact height-correlated Smith visibility and no energy compensation. For the scene's deferred shadow light (`scn_deferred.x` = shadow alpha > 0) it applies SceneKit's deferred model: the light's own term is scaled by `1 - alpha x s` instead of being shadowed, and `SPECULAR_LIGHT -= scn_unlit x alpha x s` darkens what Godot adds outside `light()` (`scn_unlit` = emission + ambient + sky light, a fragment-to-light varying); `s` = max(shadow map, faces turned away from the light, SceneKit's large-kernel self-shadowing from `scn_deferred.yz`). Godot reports the full shadow for deferred lights (`ShadowOpacity` 1). Receivers outside a light's fixed shadow box are unshadowed (`scn_shadow_box0/1`); `light()` recognises the box's light by its Godot specular amount, which `SceneKitRuntime.FitShadows` sets to 2 + the box index (1 for every other light; SceneKit lights have no specular amount, so `light()` never multiplies by it).

**Lighting-feature variants** (Godot-only, performance; `SceneKitRuntime.ShadingVariant`, `ObserveShading`). Godot inlines `light()` into its directional, omni and spot light loops, and the deferred-shadow and LDR code sits behind uniform branches, so every material carried code that the race and town never run, which cost registers and occupancy. Each scene has lighting features that only grow: deferred shadows and positional (omni, spot) lights from its lights, LDR from a camera with `wantsHDR` false that draws it. A scene without deferred shadows and LDR gets `VariantFlags.Forward` (no `scn_unlit`/`scn_fog_amount` varyings, no deferred-shadow or LDR-clamp code), one without omni and spot lights `VariantFlags.DirectionalOnly` (`light()`'s body only for directional lights). The features are read from the scene's lights when its first node is built; a view that syncs a scene with a feature its shaders lack (an LDR snapshot camera, a deferred light added later) adds it and rebuilds the scene's nodes before it draws, in `Flush` and in `RenderIsolated`. A variant renders exactly what the full shader renders in such a scene (the race world, with its track, town and dunes, gets both; the menu and the sandbox, with deferred shadows and LDR cameras, keep the full shaders). The sky-light lookup (`scn_env_radiance`) computes its equirect coordinates with minimax polynomials instead of Metal's `atan2` and `acos` (errors 1.7e-6 and 6.4e-7 rad, 2e-5 texel of the 64 x 32 bands). Together with the shadow-box test (above) this takes 2.0-2.3 ms of GPU walltime per 1920 x 1080 frame in the default configuration (city roam 46.4 -> 51.6 FPS, race 52.2 -> 56.7) and 2.7-4.5 ms in the exact one, the look unchanged (`docs/performance.md`, "Shading and post"). `MARVIN_SHADER_DUMP=DIR` writes every composed shader to `DIR` (diagnostics).

Scene state reaches every shader through global uniforms declared in `project.godot` (`scn_fog_color`, `scn_fog_range`, `scn_ambient`, `scn_ibl`, `scn_sh0..8`, `scn_deferred` = alpha, self-shadow plateau and onset, `scn_shadow_box0/1` = world-to-box matrices of up to two fixed shadow boxes, zero when unused (their lights carry 2 + the box index as Godot specular amount), and the samplers `scn_radiance` and `scn_ssao`), set by the runtime from the scene shown by the active view. `scn_radiance` (`SCNScene.RadianceTexture`) holds the `lightingEnvironment` resampled to 64 x 32 and convolved with GGX lobes for roughness 0, 0.2 ... 1.0 (six stacked equirect bands, linear float, about 30 ms on 8 threads when the probe changes); SH still provides the diffuse part. `scn_ssao` (R16F, at least 1920 x 1200) holds the SSAO factor of the view being drawn at its pixel positions: each view's `SCNSsaoEffect` writes it after Godot's depth prepass (a view without SSAO clears it to 1), and materials read it with `texelFetch(scn_ssao, ivec2(FRAGCOORD.xy), 0)`.

### Shader modifier translation guide

Shader modifiers are written in **Godot shading language**, keeping SceneKit's pragma structure. Translate each MSL snippet when you port its file:

- Keep `#pragma arguments`, `#pragma varyings`, `#pragma declaration`, `#pragma body`, `#pragma transparent`. Text before the first pragma is a declaration; a snippet without pragmas is all body.
- Arguments become uniforms set by `setValue(_:forKey:)`: `float3 x;` -> `vec3 x;`, `float4x4` -> `mat4`, `texture2d<float> t;` -> `sampler2D t : filter_nearest;` (put the sampler state in hints; `NSValue.point` -> `vec2`, numbers -> `float`, `SCNMaterialProperty`/`MTLTexture` -> `sampler2D`).
- Varyings: declare `float x;` and write/read `x` directly (drop `out.` and `in.`). `half` -> `float`.

| SceneKit | Godot (inside the snippet) |
|---|---|
| `_geometry.position` (model space, `.geometry`) | `VERTEX` (vec3; `vec4(VERTEX, 1.0)` where a float4 is needed) |
| `_geometry.normal`, `_geometry.tangent` | `NORMAL`, `TANGENT` |
| `_geometry.color` | `COLOR` (float RGBA) |
| `_geometry.texcoords[n]` | `SCN_TEXCOORDn` (`UV`, `UV2`, `CUSTOM0.xy`, ...) |
| `_surface.diffuse.rgb` / `.a` | `ALBEDO` / `ALPHA` (`ALPHA` only exists when the material is transparent) |
| `_surface.diffuseTexcoord` | `scn_diffuse_texcoord` |
| `_surface.normal`, `_surface.position`, `_surface.view` (view space) | `NORMAL`, `VERTEX`, `VIEW` |
| `_surface.roughness`, `_surface.metalness`, `_surface.ambientOcclusion` | `ROUGHNESS`, `METALLIC`, `AO` |
| `_surface.emission` | `EMISSION` |
| `_surface.selfIllumination` | `scn_self_illumination` (vec3, the material's selfIllumination, black by default). Do not drop it: merely mentioning it makes SceneKit take a physically based material's diffuse sky light from it (measured), and the composer does the same when a snippet contains the name |
| `_surface.multiply.rgb` | `scn_multiply` |
| `scn_frame.inverseViewTransform`, `viewTransform`, `projectionTransform` | `INV_VIEW_MATRIX`, `VIEW_MATRIX`, `PROJECTION_MATRIX` |
| `scn_node.modelTransform` | `MODEL_MATRIX` |
| `scn_node.modelViewTransform` | `MODELVIEW_MATRIX` (vertex) / `VIEW_MATRIX * MODEL_MATRIX` (fragment) |
| `scn_node.inverseModelViewTransform` (fragment) | `inverse(MODEL_MATRIX) * INV_VIEW_MATRIX` |
| `u_time`, `scn_frame.time` | `TIME` |
| `discard_fragment()` | `discard` |
| `float2/3/4`, `half4`, `uint2`, `float4x4` | `vec2/3/4`, `vec4`, `uvec2`, `mat4` |
| `atan2(y, x)`, `fmod`, `saturate(x)`, `rsqrt` | `atan(y, x)`, `mod` (floored; equal for non-negative operands), `clamp(x, 0.0, 1.0)`, `inversesqrt` |
| `t.read(uint2(p))`, `t.sample(sampler, uv)` | `texelFetch(t, ivec2(p), 0)`, `texture(t, uv)` (`constexpr sampler(address::clamp_to_zero)` -> multiply by an inside-[0,1] test) |
| `#pragma transparent` | unchanged (the material blends) |

`.fragment` runs after lighting in SceneKit; Godot has no hook there, so use these idioms (the composer runs `.fragment` code last in `fragment()`, after `ALPHA` and `FOG` are set):

| SceneKit `.fragment` | Godot |
|---|---|
| `_output.color.rgb *= a; _output.color.a = a;` (premultiplied alpha, `#pragma transparent`) | `ALPHA = a;` |
| `_output.color = float4(c, 1.0);` on `.constant` (replaces the fogged colour) | `ALBEDO = c; EMISSION = c; FOG = vec4(0.0);` |
| `_output.color.rgb *= k;` (scalar, lit material) | `ALBEDO *= k; EMISSION *= k;` (specular is not scaled) |
| reading the fog amount | `FOG.a` (fog colour `FOG.rgb`) |

### Lights, cameras, scenes, views

- `SCNLight`: directional/omni/spot -> `Light3D` child of the node (energy = intensity/1000, colour linearised then re-encoded, `temperature` tint). Ambient lights feed `scn_ambient`. Shadows: `ShadowOpacity` = shadow alpha (forward) or 1 (deferred, see the composer's `light()`); single orthogonal split for one cascade; `DirectionalShadowMaxDistance` = `min(maximumShadowDistance, max(4 x orthographicScale, 10))` when SceneKit adjusts the projection. A fixed box (up to two lights) is reproduced per camera: the composer's `light()` treats receivers outside the box as unshadowed, and `FitShadows` keeps the calibrated single split up to `min(maximumShadowDistance, orthographicScale)` from the camera; when the box reaches further into the view (the farthest view depth of box ∩ frustum, `SCNLight.ShadowBoxFarDepth`), it switches to two splits (`Parallel2Splits`, no blending) with the calibrated fit as the first split and the second out to that depth. Godot halves the light's atlas region for splits (its normal-bias texel doubles, so the normal bias is halved: `SplitNormalBiasExponent`) and scales the second split's PCF kernel by split1/split2, which keeps its world size within about 10%. The directional shadow atlas is 8192 (two 4096-class suns), hard filter (SoftHigh in the exact configuration: Shadow quality Exact on the Settings screen, or `MARVIN_SCN_CAL=Exact`; see "Known deviations"). Under the hard filter the fixed boxes get four splits instead (`SceneKitRuntime.NearSplitDistances`, `SceneKitCalibration.HardShadowSplit1`/`HardShadowSplit2`): ending 12 and 30 m from the camera, at `orthographicScale` and at the box's farthest view depth rounded up to steps of 25 % (`HardShadowFarStep`), each a quarter of the light's atlas region (2048 x 4096). The distances are fixed in metres, so Godot's texel snapping (each split's square light-space extent comes from the bounding sphere of its frustum slice) keeps the first three splits still while the camera moves; the last one changes only at a step. With the race camera at 1080p the texels are 1.2 / 2.8 / 5.3 / 14 cm across the light and half that along its y axis, instead of 2.9 cm to 58 m and 7 cm beyond. The race world's flat base terrain does not cast under the hard filter (`SceneKitCalibration.BaseTerrainCastsShadow`): it shadows nothing visible but filled every split, and leaving it out pays for the extra splits (`docs/performance.md`, "Near shadow splits").
- **Per-camera shadow fit** (`SceneKitRuntime.FitShadows`, after each view's camera sync): Godot fits a directional shadow map to the camera frustum, its PCF kernel is `blur x quality radius x texel` and its depth bias is `bias/100 x depth range x blur x quality radius` (Godot source, `light_storage.cpp`), so both change with the camera. The facade recomputes Godot's fit (frustum slice bounding sphere, atlas region per light: 4096 x 8192 for two lights, the coarse axis is used) and sets `ShadowBlur` so the kernel has SceneKit's world size (`0.88 x shadowRadius x 2 x orthographicScale / shadowMapSize` for a fixed box; `shadowRadius` Godot texels for an automatically fitted one), `ShadowBias` = (1 + 0.6 x kernel texels) Godot texels in world units and `ShadowNormalBias` = 2 + 0.8 x kernel texels (no PCF acne on lit slopes, measured on spheres and floors). That is the soft filter of the exact configuration. The hard filter (the default) takes one bilinear depth comparison and has no kernel, so `ShadowBlur` only scales Godot's depth bias (cancelled as above) and the biases have no kernel terms: `ShadowBias` = `HardShadowBiasTexels` (1) Godot texel and `ShadowNormalBias` = `HardShadowNormalBias` (2, Godot's default), retuned for it (`SCNLight.FitShadow`; probes and captures in `docs/performance.md`, "Hard shadows and camera mesh LODs"). With the near splits the fit is that of the first split, and Godot scales both biases per split with its size; the normal bias is scaled so it stays one of the split's coarser texels (across the light), as with the orthogonal fit.
- `categoryBitMask`: SceneKit bits are mapped to Godot's 20 render layers on first use. A node the camera mask excludes but a shadow-casting light includes casts `ShadowsOnly` (TownShadowBatch proxies).
- `SCNCamera`: copied each frame into the view's `Camera3D` (vertical FOV with `KeepAspect.Height`; `orthographicScale` is half the height). Linear tonemap, exposure 2^`exposureOffset`, glow for bloom (additive, intensity 0.15 x `bloomIntensity`, levels 1 .. round(log2(`bloomBlurRadius`) - 0.6), independent of resolution), SSAO through the view's `SCNSsaoEffect` (SceneKit's algorithm, see "Measured SceneKit semantics"; Godot's own SSAO stays off).
- `SCNScene`: a `World3D` and a hidden host `SubViewport` holding `rootNode`; `background.contents` colour or panorama; `lightingEnvironment` -> SH for the composer (Godot's ambient and reflections are disabled).
- `SCNView` (a `SubViewportContainer`) and `SCNRenderer` render the scene's world with their own camera and environment, so one scene can be shown by several views. `snapshot()` renders synchronously (`RenderingServer.ForceDraw` after forcing transform updates). `projectPoint`/`unprojectPoint` use AppKit coordinates (origin bottom-left, z 0..1). `isNode(_:insideFrustumOf:)` tests the node's bounding box against the view frustum.
- Per frame the runtime (`SceneKitRuntime`, last in `_Process`) runs queued `DispatchQueue.main` blocks, then flushes dirty materials, node transforms/meshes/lights, evaluates constraints (render transform only, like SceneKit's presentation tree), syncs view cameras and scene uniforms. It pushes only what changed: a node's transform is recomputed only when its model values changed, mesh instances get cast-shadow/layer/transparency/visibility only on a change, nodes outside every scene (the race's pooled particle slots) keep their transform and visual changes until they are added (their meshes and material variants are still built in order, since creation order decides Godot's draw order among equal-depth surfaces), and the transparent sort is skipped when neither the camera nor any transform, visibility or transparent instance changed since the last sort (see `docs/performance.md`, "CPU pass").
- Threads: `LevelLoading` builds `DirtWorld` on a global queue and hands it to the main queue; that works unchanged. Godot lets any thread change nodes that are outside the scene tree, so an `SCNScene` created off the main thread stays detached, and changes made off the main thread (dirty nodes, materials, textures, constraints) are parked. The main thread adopts them when it takes the objects over: when a scene is assigned to an `SCNView`/`SCNRenderer`, and when `addChildNode` attaches a subtree built elsewhere. `NSGraphicsContext.current` is per thread, as in AppKit. Do not change objects that are already shown from another thread (SceneKit tolerates it, Godot does not), and do not block the main thread on a builder thread: Godot answers some of the builder's RenderingServer calls (creating a scene's viewport) on the main thread. The facade test builds the same content on the main thread, as a whole scene on a pool thread and as a subtree on a pool thread, and checks the renders are identical.
- `SCNView`/`SCNRenderer.prepare(_:completionHandler:)` is asynchronous, as in SceneKit (`SceneKitRuntime.PrepareAsync`): the scene's mesh arrays and procedural textures (mipmaps) are computed on worker threads, the main thread hands the nodes whose data is ready to Godot for at most 10 ms per frame, and the handler runs when all of them are flushed; the game keeps the loading screen up meanwhile. `prepare(_:shouldAbortBlock:)`, snapshots and `SCNTransaction.flush()` flush everything at once (`FlushAll`). Material properties whose contents are `res://` image paths start loading the imported texture on Godot's loader threads when the contents are set (`NSImage.Preload`), so a scene built on a background queue finds them loaded.

### Known deviations

- **Hard shadows and camera mesh LODs** (the default since ef7b4e6, chosen for frame rate at 1080p: race 34.0 -> 46.9 FPS, town roam 29.7 -> 39.2 FPS on an M2, `docs/performance.md`, "Hard shadows and camera mesh LODs"). The directional shadows use Godot's hard filter, one bilinear depth comparison, instead of the SoftHigh kernel that reproduces SceneKit's penumbra width, and the robots' camera images use the same mesh LODs as their shadows. Shadow edges are about one Godot texel wide instead of SceneKit's 11.5-16 cm (race suns) and 4 cm (menu key light) penumbrae. Since the near shadow splits ("Lights, cameras, scenes, views"; `docs/performance.md`, "Near shadow splits") the suns' texels are 1.2 x 0.6 cm within 12 m of the race camera, 2.8 x 1.4 cm to 30 m, 5.3 x 2.7 cm to 58 m and about 14 x 7 cm beyond; before, they were 2.9 cm to 58 m and 7 cm beyond, and close views showed them as blocks and stair-steps (Marvin's head shadow across its body in the race-grid close-ups, the race-light robot close-ups, the dunes' contact views). Next to the camera the texels are now 2.4-4.8 times smaller and their edges crisp, sharper than SceneKit's: at the race grid's distances they read as clean lines, but where a pixel is a millimetre or two (the race-light and dune-contact close-ups, a walker's feet, the base of a wall next to the camera) they still show as small stair-steps; the finer map also resolves thin casters SceneKit's filtered map blurs away (R2-D2's feet and WALL-E's tread plates are shaded more in the race light, a robot dome right in front of the camera at a low sun shows its rim's shadow), and the overviews' far shadows have coarser texels than before. Where the two suns' shadows overlap, the weaker sun's shadow shows as a lighter band beside the dark core instead of blending into one soft edge; the menu's and sandbox's faint deferred shadows have crisp outlines. The hard filter has its own biases (`HardShadowBiasTexels` 1, `HardShadowNormalBias` 2, without the soft filter's kernel terms), which leaves no acne in the probes or in the captures looked at and puts edges about where SceneKit has them (with the earlier fit 6.8 cm towards the caster at a 10 degree sun; SceneKit 7.8 cm, the soft filter 24.7 cm). Robot silhouettes move by up to half a pixel. Over the full-game comparison the mean difference from macOS went from 1.77 to 1.96/255 with hard shadows and to 2.06 with the near splits (per area below), which trade the large blurred blocks for smaller, crisp ones. The player can choose the exact configuration and its GPU cost on the Settings screen (Shadow quality Exact, next bullet); `MARVIN_SCN_CAL=Exact` (or `MARVIN_SCN_CAL="ShadowFilterQuality=4;MeshLodForCamera=0;BaseTerrainCastsShadow=1"`) selects it for any mode, in the editor runtime and in the exported builds; `MARVIN_SCN_CAL="HardShadowSplit1=0;BaseTerrainCastsShadow=1"` gives the hard filter the earlier split fit. The calibration results and the earlier comparisons in this document were measured with the exact configuration.
- **Shadow quality setting** (Godot-only; the macOS Settings screen has no such control, SceneKit's soft shadows cost its GPU little). The Settings screen has a seventh row, "Shadow quality: Fast / Exact", between Braking assist and Back (`MainMenuView.exactShadows`, `scripts/UI/ShadowQualitySetting.cs`): Fast is the default above (hard shadows with near splits, camera mesh LODs), Exact the exact-SceneKit configuration (`SceneKitCalibration.ApplyExact`: SoftHigh penumbrae, full robot meshes, the base terrain's shadow), which at 1920 x 1080 on this Mac runs the race at about 42 instead of 53 FPS and the town roam at 36 instead of 49 (`docs/performance.md`, "Near shadow splits" and "Ground and overlays"). The choice is stored with the other settings (`UserDefaults` key `shadowQuality`, "Fast" or "Exact"; absent = Fast) and **applies immediately**, in the menu's portrait at once and in a race or sandbox entered afterwards, without a restart: the filter quality is a global RenderingServer setting, the splits and biases are refitted at every camera sync anyway, the robots' shadow-only twins are rebuilt at the next flush (`SceneKitRuntime.ShadowConfigurationChanged`) and an already built race world's base terrain follows (`DirtWorld.baseTerrain`). Measured: a switch at run time renders exactly what a launch with that configuration renders (to Exact: the menu captures and all 43 `--visual-regression-test` captures with its pin, and its report, pixel-identical to an `MARVIN_SCN_CAL=Exact` launch; to Fast: the same captures identical to a default launch), and the frames after a switch took 16-17 ms (no hitch). The game launched normally (no game-mode flag) starts with the stored choice (`scripts/Main.cs`); game modes (smoke checks, benchmarks, probes, the playthrough) keep Fast unless their own menu check uses the row, so a stored Exact never changes their reports or timings. `MARVIN_SCN_CAL`, when set, chooses the configuration for tests and experiments instead: the row then only changes the stored choice. To make room the settings rows keep the Mac's spacing where it fits and move closer on short views (the 900 x 550 QA layout, the smallest window's 900 x 612 content); `driving-assist-settings.png` (1280 x 792) is unchanged down to the fifth row and shows the extra row and the hint 54 points lower (0.18 -> 0.76/255 from macOS).
- Image-based specular uses an analytic split-sum environment BRDF: within 0.021 linear of SceneKit at grazing views (up to 20% on rough dielectrics at 80°); very rough metals do not brighten towards the silhouette as in SceneKit. SSAO is SceneKit's algorithm, but its input is Godot's depth prepass resolved from MSAA rather than SceneKit's own pass (`.geometry`-modified pixels and the sky hold z +1 but not their colour), and the 13-tap blur runs in single rather than half precision.
- SceneKit's fixed orthographic shadow box (`automaticallyAdjustsShadowProjection = false`) is reproduced by clipping and a second split (above), but Godot still renders camera-fitted maps: the far split has coarser texels than SceneKit's box (about 6 cm instead of 2.8 cm in the race views), split maps halve the resolution along the light's y axis (race_evening_chase 1.56 -> 1.67/255, race_midday_chase 1.11 -> 1.05), the split is chosen from the box alone (parts under the ground count), and casters in front of the light's `zNear` still cast. The hard filter's near splits are finer than SceneKit's box within 30 m of the camera and coarser beyond it (across the light 5.3 cm to 58 m and about 14 cm further out, instead of 2.83 cm for sun A and 5.66 cm for sun B). The bias is refitted per camera, and in the exact configuration the penumbra too, to SceneKit's world size. Godot's normal-offset bias removes the acne SceneKit shows at grazing sun angles and makes shadows leak a few centimetres at contact edges. An automatically fitted SceneKit shadow map is assumed to have Godot's texel size (SceneKit fits tighter in close-ups).
- Shadow bias of the fixed-box suns (`GroundBiasProbe`, `tools/godot -- --ground-bias-probe DIR`). Without a caster bias Godot's PCF let a casting ground darken the lowest 5-8 cm of every sunlit wall standing on it (0.20 darker at 2 mm, at every sun elevation; SceneKit 0.004), which also failed `--ground-performance-test` at the low sun (the covered terrain's 4 m cells cast; the 256 m reference plane's two triangles did not, because Godot's directional shadow pancaking distorts the depth of vertices far outside the light's frustum: measured with `DirectionalShadowPancakeSize` 0). The composer's shadow-pass slope bias (2.6 SceneKit texels, about the PCF kernel's radius) removes it: the walls now match SceneKit to 0.004 and the check passes. Still different: Godot keeps its receiver normal bias, so a thin caster close above a receiver casts later than in SceneKit (in the exact configuration a 1 cm plate's shadow is half there at a gap of about 15 cm instead of 7.5 cm for the 4096 map, as before the slope bias, and 24 cm instead of 15 cm for the 2048 map; with the default hard filter's biases at 8 and 16 cm; through the race camera's lens with the near splits at about 7, 9 and 13.5 cm 3, 14 and 40 m from the camera, the probe's test E). A smaller normal bias (0.5 texels matches SceneKit's plates) makes the town's shadow proxies, which have no normals for the slope bias, self-shadow in fine stripes at a low sun.
- Deferred shadows assume one deferred shadow-casting light per scene (the game's sandbox and menu); a non-black `shadowColor` is treated as black. SceneKit's large-kernel self-shadowing is reproduced as a fitted function of the angle to the light (measured on spheres). Emission above 1 in an LDR view is darkened before SceneKit's 8-bit clamp in Godot, so very bright emissive surfaces in deferred shadow stay clipped white. SceneKit skips deferred shadows on constant materials under orthographic cameras; the facade does not.
- Reflections come from `lightingEnvironment` resampled to 64 x 32 and pre-filtered into six GGX bands (sharp horizon in chrome as in SceneKit); detailed environment images lose detail beyond that resolution. Diffuse sky light uses order-2 SH.
- Godot samples mipmaps trilinearly and applies one global anisotropy level; SceneKit's default `mipFilter = .nearest` and per-property `maxAnisotropy` are not reproduced. `wrapS != wrapT` is not supported (the game never mixes them).
- `.fragment` modifiers cannot read the lit colour; use the idioms above. Exposure adaptation, vignetting, colour fringe, motion blur and depth of field are not emulated (the game leaves them off).
- Premultiplied `NSBitmapImageRep` texels with colour > alpha (WindblownDust's white-with-density texture) are clamped. SceneKit decodes them as extended sRGB while the premultiplied linear value stays below 1 and wraps chaotically above it (measured over all 256 x 256 colour/alpha pairs; white at alpha 64 renders as premultiplied black, at alpha 128 as premultiplied 0.78 instead of 0.5). The white dust sprite therefore darkens its background 5-30% more in SceneKit than in the facade (single-sprite probe, lambert, lit from either side); the garbage values are not emulated.
- `SCNFloor` reflections, `SCNRenderer.render(withViewport:commandBuffer:passDescriptor:)` and Metal capture APIs are not implemented; `snapshot(atTime:)` does not drive shader `TIME`.
- `presentation` returns the node itself; constraints only move the rendered transform. Nodes removed from a scene and dropped are not freed automatically (Swift's ARC frees them): game code calls the PORT helper `releaseRemoved()` where the Swift code drops a removed node for good (DirtTrail's chunks and DeformableSand's patches on a reset or eviction, the sandbox's rebuilt floor details); before, every race reset left its trail chunks behind as orphan nodes (100-130 per reset after 30 s of racing).
- `DirtCoating` still creates a new 2 x 1 contact texture per upload, as the Swift code does: Marvin's and R2-D2's coated parts end with a primitive geometry, so SceneKit keeps drawing their first contents and only in-place writes would show (see `SCNMaterialProperty.ArgumentContents`). `DeformableSand` updates each patch's height texture in place instead (PORT comment): its geometry is custom, so contents changes and in-place writes show alike.
- Global scene uniforms (fog, ambient, IBL) come from the last view rendered in a frame; two visible views showing different scenes at once would share them. Snapshots (`SCNView.snapshot()`, `SCNRenderer.snapshot(...)`) render their viewport alone with its own scene's uniforms (`SceneKitRuntime.RenderIsolated`), so an offscreen renderer of another scene is exact (VisualRegressionSmoke's QA scene was lit by the race scene's sky light before: 5-7/255 from macOS, now 0.15-1.5/255; the debris check's `SCNRenderer` capture, taken while the main menu showed, was lit by the menu's ambient light: clod colours 0.43/0.23/0.13 instead of SceneKit's 0.525/0.286/0.165, now exact). A snapshot whose camera has another `categoryBitMask` than the window's applies that mask before it draws (the town's shadow-batch proxies, white constant geometry hidden from the race camera only, showed in VisualRegressionSmoke's first track close-up after its QA scene).
- Text uses the platform fonts Godot finds, rasterised unhinted by FreeType. CoreText draws SF caps up to 0.7 px taller at 12, 16 and 18 pt (snapped to whole pixels, measured with font smoothing off; x-heights similarly, e.g. 17 pt x-height 9 px instead of 9.35); not reproduced (FreeType's light hinting matched worse overall), so text at those sizes has up to 4 % more or less ink and softer tops. CoreText's dilation is emulated by FreeType emboldening (ink within 1.5 % mean); `draw(in:)` does not wrap lines; the CPU bitmap path places glyphs on whole pixels. Images drawn into a `lockFocus` NSImage are 1x (AppKit backs them at the screen's scale, 2x on Retina), so the minified town map in the DUNES view is a little thinner than the Mac's.
- `colorAt(x:y:)?.usingColorSpace(.deviceRGB)` returns the stored sRGB components unchanged. On macOS a snapshot bitmap is tagged sRGB and the conversion goes through the display profile, which lifts mid-tones (measured on this Mac: sRGB 0.826 grey reads 0.860, the clay clod colour (0.525, 0.286, 0.165) reads (0.601, 0.361, 0.216)). Numbers that macOS smoke modes print or store after such a conversion (sun occlusion luminance, rendered clod colours, trail-material ratios) are therefore a little higher there for identical pixels.
- AppKit views: Auto Layout is limited to equalities between edges, sizes and centres (enough for overlays pinned to the content layout guide), solved when the guide changes; a frame assigned directly stays until then (AppKit re-solves at its next layout pass). `SCNView.frame` stays in Godot pixels (top-left origin); cursor rects apply to the whole view; `NSAlert.runModal()` does not block.
- Window chrome: the title bar and toolbar are drawn by the facade (vector stand-ins for SF Symbols, AppKit's pre-macOS 26 metrics); the toolbar cannot be customised; on Windows the system title bar sits above the 1280 x 820 client area and the facade's bar holds the menu bar. On a HiDPI screen the views keep their point sizes, AppKit drawing and text are rendered at the backing resolution, and the SCNView renders 3D at the drawable's pixel size (bounds x backingScaleFactor), as SceneKit does. This Mac's display is 1x: the HiDPI path was exercised with the test hook `MARVIN_BACKING_SCALE` (1.25: 1600 x 1025-pixel window, 1280 x 820 points, the playthrough passes; 2: the town benchmark's 1080p drawable, see "Performance"), not on a Retina screen or on Windows.

Measured on macOS 27 with offline AVAudioEngine renders and reproduced (`tools/godot -- --audio-facade-test DIR` checks 66 values against the macOS numbers): source volume/pan apply at the downstream mixer input even through effects; pan is a balance law; mixer gains slew per channel at 1/1200 per frame (first render snaps, a stopped direct player freezes its ramp); `outputVolume` ramps over one render; varispeed rate applies per render with a 48-frame input delay; `.lowPass` is a bilinear Butterworth whose frequency glides log-linearly over 1440 frames; AUPeakLimiter (lookahead 96 frames, ramp slope `(-peak dB - gain dB)/86` per frame, ramps restarted by louder peaks, hold while a peak is in the window, release half-life 5 ms) matches Apple's output within 1e-5 on tones, spikes and noise; `play()` starts at the engine's sample time on the player's own render timeline, so offline a restarted loop behind a slowed varispeed stays silent until it catches up (as in the macOS evidence WAVs), while a real-time engine restarts its timeline. A running real-time engine renders on its own thread into a 48 kHz `AudioStreamGenerator` (`AVAudioEngineOutput` under the root, about 32 ms queued; 100 ms on the headless Dummy driver). `--audio-smoke-test` renders the same evidence WAVs and `audio.json` as macOS: per-stage levels match within 0.2 dB (Marvin, city and storm within 0.04 dB), whole-file levels within 0.06 dB. Deviations: the resampler is a 24-tap windowed sinc rather than Apple's converter (residual interpolation differences, about 0.1 dB per second of motor sound); the residual burst after an offline restart is about 1 dB weaker; raw `.wav` files are read from `res://assets/Audio` (exports fall back to Godot's imported 16-bit PCM).

With `--benchmark-isolate-trails` (a second run, with another job's Godot running), hiding the trails at 300-330 s gave 58.8 FPS (54.5 before) but at 480-510 s nothing (54.0), the same inconclusive pattern as the macOS investigation (sustained-fix/plan.md), so the drop is not attributed. The node count grows by about 800 over the run (5,066 to 5,876: trail chunks). `check-sustained-performance.py --scope cadence` reads the Godot run and fails it on the resolution (960 x 540 on this screen), the gaps over 25 ms and the frame coverage.

**Where the 1080p GPU time goes** (Metal System Trace and benchmark flags at 1920 x 1050): about 20 ms of Godot GPU work per frame, mostly fragment shading: the opaque pass 6 ms, the transparent pass (town ground overlays, trails, dust, lit with both suns' soft shadows) 3.3 ms, SSAO about 1.5 ms, bloom 0.6 ms. Directional shadows cost about 7.5 ms in all: `--benchmark-no-shadows` gives 49-50 FPS, Godot's hard shadow filter instead of SoftHigh's 16 taps per light (`MARVIN_SCN_CAL=ShadowFilterQuality=0`) 39 FPS; turning off the robots' or the town's shadow casting changes nothing, so the cost is in sampling and the four 4096-texel map passes (two suns x two splits), not in the casters. Godot's pipeline is fragment-heavy where SceneKit's is vertex-heavy, so it uses less GPU than SceneKit at 960 x 540 but more at 1080p. Reaching 1080p at 60 FPS on an M2 would take quality changes (fewer shadow filter taps, one split, lower SSAO quality), which this pass did not make.

## Validation

- **Logic:** `tools/checks` must print the same values as `reference/simulation-checks-swift.txt`, the macOS SimulationChecks output at the same commit. On macOS the numbers should match exactly.
- **Visuals:** compare captures of the same scene, camera and state against the macOS game's captures. Run the macOS game's own capture modes (`'apps/simulator-macos/.build/Marvin Simulator.app/Contents/MacOS/MarvinSimulator' --smoke-test DIR`, `--town-smoke-test DIR` and others; see its README) and add matching capture modes to the Godot game (`tools/godot -- --capture <name> DIR`). Inspect both images side by side. A passing number is never visual acceptance.
- **Behaviour:** port the macOS smoke checks that verify gameplay, and keep their JSON report keys.
- **Random state of a macOS run:** smoke modes draw the starting grid and the daylight at random on every `reset`. `AppController.reset(_:)` can pin them (`TestPins` in `scripts/App/AppModes.cs`) so a capture compares 1:1: `MARVIN_GRID_SLOTS=i,j,k,l` (or `MARVIN_TOWN_GRID`; indices into `DirtCourse.startingGrid` for player, R2-D2, BB-8, WALL-E; grids separated by `;` pin one reset each, the last repeats) and `MARVIN_DAYLIGHT_FRACTION` / `MARVIN_DAYLIGHT_PHASE` (comma-separated lists, one entry per reset, the last repeats; `MARVIN_TOWN_DAYLIGHT=fraction,phase` pins every reset). The grid of a macOS `--smoke-test` run is the permutation whose 240-frame trail counts reproduce `racerTrailMarks` exactly (the reference run in `reference/mac/smoke` is `0,3,1,2`); its daylights were fitted by rendering candidate fractions and phases against the track and sky pixels (`0.515,0.795` / `2.75,2.065` for that run; town smoke `0.2125` / `4.18`). The third reset of that run (RaceFinishSmoke's race-start.png and race-pause.png) was fitted with `--fit-race-start`: grid `3,1,2,0`, daylight `0.8305` / `2.5753`. So the reference smoke run is reproduced by `MARVIN_GRID_SLOTS="0,3,1,2;0,3,1,2;3,1,2,0" MARVIN_DAYLIGHT_FRACTION=0.515,0.795,0.8305 MARVIN_DAYLIGHT_PHASE=2.75,2.065,2.5753` (race-start 1.51/255, race-pause 1.61/255 against macOS, from 10-11/255 with the third reset unpinned). The playthrough pinned to that reset (`MARVIN_GRID_SLOTS=3,1,2,0 MARVIN_DAYLIGHT_FRACTION=0.8275 MARVIN_DAYLIGHT_PHASE=2.6626`) reaches the same view after its intro fly-in: its race-start is 1.55/255 and its race-pause (the P key) 1.65/255 from the macOS smoke captures. `--fit-race-start DIR MAC.png` also fits other post-reset captures; with `MARVIN_FIT_STORM=1` it renders the drawn sandstorm (SandstormSmoke's weather reset: its storm reset `overlay-storm-countdown.png` and its clear reset `overlay-clear-countdown.png` are the second and third resets of `--weather-reset-test`). A `--character-smoke-test` run has eight dirt resets (startDirtTrack and the reset after the race, per character in the order b r w m); `--fit-character-race` prints all of them.
